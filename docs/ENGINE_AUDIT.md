# Engine audit — official libslic3r (not a rewrite)

**Date:** 2026-08  
**Branch:** `ios-port`  
**Verdict:** **Official engine wrapper**

## What this means

Slicing on iOS uses the **same** `src/libslic3r` C++ tree as desktop OrcaSlicer. The mobile shell is SwiftUI + a thin C ABI; it does **not** reimplement Arachne, supports, infill, or G-code generation.

```
SwiftUI (ios/OrcaSlicerApp)
    → orca_session_*  (src/ios/orca_slice_c_api.cpp)
        → Slic3r::Model / DynamicPrintConfig / Print
            → Print::apply → Print::process → Print::export_gcode
                → full upstream libslic3r
```

## Proof points

| Check | Result |
|-------|--------|
| CMake links `orca_ios_api` → `libslic3r` | Yes (`src/ios/CMakeLists.txt`) |
